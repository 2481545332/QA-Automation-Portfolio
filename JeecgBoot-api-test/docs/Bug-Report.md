# JeecgBoot 1.0 接口自动化测试缺陷报告

**测试模块**：登录模块 / 部门角色模块 / 知识库文档模块  
**测试人员**：自动化测试组  
**报告日期**：2026年11月6日  
**缺陷总数**：5 个（P0: 2个，P1: 1个，P2: 1个，P3: 1个）

## 🔴 P0 级：致命安全漏洞（需立即修复）

### 缺陷 1：研发部账号可越权篡改财务部机密文档
*   **缺陷编号**：BUG-DOC-001
*   **所属模块**：知识库文档模块
*   **严重程度**：致命 (Critical)
*   **优先级**：紧急 (High)
*   **发现方式**：接口自动化测试 (DOC-10 用例)
*   **前置条件**：财务部账号造一条文档，获取其真实 ID。
*   **复现步骤**：
    1. 使用研发部账号登录，获取 Token。
    2. 调用编辑接口 `/sys/files/edit`，请求体传入财务部的文档 ID 和修改后的名称。
    3. 接口返回 `success: true`。
    4. 连库查询 `sys_files` 表。
*   **实际结果**：接口返回 200 成功，数据库中的文件名称被成功篡改。
*   **预期结果**：应校验部门权限，返回 403 无权限或业务异常。
*   **修复建议**：编辑接口增加数据归属校验，SQL 中补充 `depart_id` 条件。

### 缺陷 2：研发部账号可越权物理删除财务部文档
*   **缺陷编号**：BUG-DOC-002
*   **所属模块**：知识库文档模块
*   **严重程度**：致命 (Critical)
*   **优先级**：紧急 (High)
*   **发现方式**：接口自动化测试 (DOC-15 用例)
*   **前置条件**：财务部账号造一条文档，获取其真实 ID。
*   **复现步骤**：
    1. 使用研发部账号登录，获取 Token。
    2. 调用删除接口 `/sys/files/delete`，传入财务部的文档 ID。
    3. 接口返回 `success: true`。
    4. 连库查询该 ID。
*   **实际结果**：接口返回 200，数据库记录消失（物理删除）。
*   **预期结果**：应拦截跨部门删除请求。
*   **修复建议**：删除前增加归属校验；建议改为逻辑删除（更新 `del_flag`）以防数据永久丢失。

## 🟠 P1 级：严重功能阻断（影响主流程）

### 缺陷 3：部门角色列表查询恒返回空数据 (total=0)
*   **缺陷编号**：BUG-ROLE-001
*   **所属模块**：部门角色模块
*   **严重程度**：严重 (Major)
*   **优先级**：高 (High)
*   **发现方式**：接口自动化测试 (LIS-01 用例)
*   **前置条件**：数据库 `sys_depart_role` 中已存在多条角色数据。
*   **复现步骤**：
    1. 使用 Admin 账号登录。
    2. 调用 `/sys/sysDepartRole/list` 接口，传参 `pageNo=1, pageSize=10`。
    3. 查看返回结果。
*   **实际结果**：接口返回 `success: true`，但 `total: 0`，`records: []`。
*   **预期结果**：返回真实的记录数和数据列表。
*   **修复建议**：排查后端 DataScope（数据权限）拦截器的 SQL 拼接逻辑，可能由于权限过滤导致加入了永假条件（如 `1=0`）。

## 🟡 P2 级：一般健壮性问题（易产生脏数据）

### 缺陷 4：写接口缺乏参数强校验及事务回滚机制
*   **缺陷编号**：BUG-SYS-001
*   **所属模块**：全局模块（角色/文档）
*   **严重程度**：一般 (Major)
*   **优先级**：中 (Medium)
*   **发现方式**：接口自动化测试 (ADD-02, EDT-04, DEL-02 等)
*   **复现步骤**：
    1. 调用新增接口，传入 `roleName=""` 或 `fileName=""`。
    2. 调用删除接口，传入不存在的伪造 ID（如 `fake_id_9999`）。
    3. 调用批量删除接口，传入混合了真实 ID 和伪造 ID 的参数。
*   **实际结果**：
    1. 空字符串直接落库成功。
    2. 删除不存在的 ID 也返回“删除成功”。
    3. 批量删除无事务，真数据被删，假数据被忽略，返回成功。
*   **预期结果**：1. 拦截空值并提示；2. 提示记录不存在；3. 触发全局回滚。
*   **修复建议**：引入 `@NotBlank` 进行入参校验；批量删除接口添加 `@Transactional` 注解。

## 🟢 P3 级：轻微规范问题（不影响功能但易误导）

### 缺陷 5：未登录状态下返回的 code 与 success 逻辑冲突
*   **缺陷编号**：BUG-AUTH-001
*   **所属模块**：登录模块
*   **严重程度**：轻微 (Minor)
*   **优先级**：低 (Low)
*   **发现方式**：接口自动化测试 (ADD-04 无Token新增)
*   **复现步骤**：不携带 Token，直接访问需要鉴权的接口（如新增角色）。
*   **实际结果**：接口返回 `code: 401`（未授权），但 `success: true`。
*   **预期结果**：`success` 应当为 `false`，保持全局返回结构的一致性。
*   **修复建议**：排查全局异常拦截器（GlobalExceptionHandler）中关于 401 异常的处理逻辑，修正 success 字段的赋值。

*(注：研发部越权查询财务文档 [DOC-06]，经测试拦截有效，未产生数据泄露，不计入缺陷，但保留为安全回归用例。)*
